# Deployment Artifacts

This directory stores network-specific contract and system-script information.

- `scripts.json` contains the deployed `hash-lock.bc` code hash and CellDep OutPoint.
- `system-scripts.json` contains known scripts, including `ckb-js-vm`.
- `<network>/hash-lock.bc/` contains deployment configuration and migration history.

Run deployment from the example root:

```bash
# Devnet
pnpm run deploy -- --network devnet

# Testnet
pnpm run deploy -- --network testnet --privkey 0x...
```

Current OffCKB supports direct deployment only to Devnet and Testnet. Its Mainnet system-script export has no `ckb-js-vm` entry, so this example cannot synchronize the dependencies required for a direct Mainnet run. For Mainnet-state inspection or debugging, use an isolated [OffCKB Mainnet fork](https://github.com/ckb-devrel/offckb).

After OffCKB reports commitment, `scripts/deploy.js` validates the selected network's `hash-lock.bc` entry, refreshes and validates its `ckb-js-vm` system-script entry, and copies both files into `frontend/deployment/`. It compares each source with its copy and treats missing, malformed, or unsynchronized artifacts as deployment failures.

OutPoints are not portable between networks and become stale after Devnet resets or redeployment. Always use the artifact generated by the deployment you just completed.
